# CIS assessment and compact overviews

Baseline: `42e5bef864399dfca882bb66ab053f8a3c3f62a8`. This follow-up changes CIS assessment presentation and only the overview above Reviews, Action Items and Risks registers. It does not change record storage, permissions, question catalogs, scoring, lifecycle commands or the Vendor reference.

## Assessment contract

The CIS editor retains its existing full shell, status/narrative fields, Items, Findings and native Save/Cancel. The official requirement is collapsible; existing cadence and source stay available. Begin/Resume opens one native question or matrix row at a time. Question IDs, versions, visible wording, help, options, branches and group-note keys come from the existing engine. Continue uses the existing group checkpoint, explicitly disclosed in the interface; it is not an assessment commit or background autosave. Pause collapses the mounted interview and retains unsaved answers locally, as the original disclosure did; those unsaved edits are not promised across reload. Explicit Save & close uses the original persistence/comparison handler. Full-editor close retains its native dirty-progress protection. Answer review and summary use the native validation and manual-replacement protection.

Other-framework editors and the default non-sequential guide retain their existing behavior. The implementation uses real CIS enrollment/configuration and existing authorization guards for IG1/IG2/IG3 in standard and Demo mode, including later program additions.

## Overview contract

The shared compact timeline receives saved native events and exact record callbacks. It uses the existing Vendor UTC calendar window. Three lanes/three Coming up entries serve Reviews/Actions; Risks adds one lane/entry while preserving every matrix cell dimension and calculation. Dense groups expose every exact event in an accessible preview; opening uses the existing full record route. View data exposes the same event set. No future record, cadence approximation or lifecycle decision is generated by the plot.

Action priority is read from Actions rather than a linked Finding's severity. Missing priority/dates remain unknown. Risk review, linked treatment Action and acceptance expiry remain separate meanings; completing a Review does not close or accept a Risk. Unavailable relationship reads are disclosed rather than shown as complete information.

Cluster Open item retains its stable timeline trigger for keyboard focus after the native editor closes. Restoration is bounded to the same actor/client/mode scope and exact event; if a save moves or removes that event, focus returns to the current timeline controls or heading. Delayed native record loading and refreshes do not change the protected editor.

Registers, search/filter/sort/pagination, native full editors, New-item flows and exports remain protected. Shared presentation changes are scoped to new overview selectors; Vendor source and stylesheet are unchanged.

## Verification boundary

Required CI and both standard/private Demo builds must pass for the delivered commit before existing staging is updated. Browser visuals, saved state, authenticated persistence and human acceptance remain separate from unit tests/builds. The coordinating receipt records exact revision/assets, actual journeys and any untested scope/zoom limitations. No merge, production deployment, reseed, shared-data reconciliation or access expansion is part of this change.
