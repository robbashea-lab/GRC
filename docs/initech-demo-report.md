## W. Known limitations / acceptance gate

**Open capacity defect:** adding a fifth three-framework client and operating it
for five simulated years reaches the existing 5,000,000-character sessionStorage
limit. The latest reproduced failure occurs during year five (2031-03-31), with
approximately 4.97 million characters already stored before the failed write. History growth, not
large evidence files, is the remaining constraint. The write fails explicitly;
the canonical four-client scenario still loads, saves and resets.

The suite is intentionally red until a separately approved persistence solution
or scope decision resolves this. A broader IndexedDB migration has not been
implemented without that decision. Clearing small files is not a durable solution
to growing historical state. No full-history deletion, quota bypass or hidden
test exclusion is acceptable.

Existing sessions are not silently reseeded. Initech appears on new Demo sessions
or explicit Reset Demo Data, which intentionally removes custom Demo edits. Normal
client data is never reseeded. Synthetic file bodies are intentionally lightweight;
the readiness register is management representation, not substitute audit proof.
Exact licensed ISO/AICPA text validation and production-like infrastructure remain
outside this change and retain the earlier framework-validation qualifications.

Existing date-presentation inconsistency observed near UTC midnight: register
relative-day labels use the viewer's local day, while a record drawer uses the
UTC management day (for example, five versus six days overdue). The literal due
date is unchanged. This needs a deliberate shared calendar-day presentation
decision; it was not hidden by changing Initech dates or silently changing all
other clients' date behavior.
