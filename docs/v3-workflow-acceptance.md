The native review and corrective-work rules resolve the earlier shorthand about closing linked work from either screen. A linked change must reach the same saved record. Entering a review result, remediating a finding and validating closure are distinct actions. No open product decision blocks the scenarios above.

The CMMC check exposed a mismatch between the existing assessment form and the native save contract. The form records an internal verification judgment, and the saved workbook already reads that field. CMMC now declares this existing capability in the same registry as CIS and SOC. The save uses the existing validation and history path. Verification is separate from the submitted SPRS record and any formal CMMC determination.

## Run before release

Run the existing staging build from `frontend` with `node scripts/staging.cjs`. In the same checkout install the runtime Python requirements and `mongomock-motor==0.0.36`, and make Playwright Chromium available as in the [release workflow](../.github/workflows/release-verification.yml). Run `node scripts/qa/approved-v3-native.cjs` from `frontend` with `APPROVED_QA_FAST=1` for the release browser checks. Set `APPROVED_QA_RECEIPT` to a writable JSON path for the receipt. For a focused diagnostic, unset `APPROVED_QA_FAST` and set `APPROVED_QA_CASE` to `CIS recurring review`, `CMMC scoring`, or `Linked workflows`. With both variables unset, the runner executes the existing longer calendar, evidence and onboarding checks in a separate disposable run.

The browser fixture binds to loopback and starts a fresh, in-memory database for each invocation. It exercises compiled pages, normal sign-in and native request handlers. The existing real-Mongo release job covers persistence and transaction properties which the browser fixture cannot establish.

Run `python scripts/qa_native_inventory.py <path-to-mongod> --matrix-only` to verify the framework matrix locally. The runner starts its own loopback replica set. CI uses the existing disposable replica set and gives each run a fresh database. The expanded matrix is advisory on v3 staging pull requests and required on v3 staging branch runs. Existing browser and release checks keep their original requirements.
