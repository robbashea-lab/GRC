# Shared content and persistence contract

Canonical CIS v8.1 IDs, titles, text, minimum group and cumulative membership remain authoritative. One definition is inherited by every eligible group; there are153 unique definitions, not three copies. Eligibility uses authorized client/program configuration, group, matching assessment client/framework and canonical in-scope ID. Tenant/server permissions, native CAS, version and history remain required.

Existing source-reviewed `definition.elements` with stable criterion IDs, text and source-conditioned exclusions form the atomic contract. Keep valid question IDs/options/meanings. Optional system/owner/evidence/narrative context never becomes a hidden substantive requirement. Examples are not mandatory technologies. Row-level conditional exclusions require a source condition and rationale; whole-record Not Applicable remains the existing authorized native decision. Unreachable status branches must be documented.

Root aggregate answers cannot override accepted atomic facts into a false pass or partial outcome. All unknown/no meaningful substantive basis is Not Assessed; supported absence is Not Implemented; meaningful implementation with material unmet/unresolved criteria is Partial; all applicable substantive criteria supported is Implemented. Contradictions and accepted alternatives need explicit source-justified cases, not percentages. Inactive historical answers are retained but excluded from current evaluation.

Keep approved safeguard1.1 v3 questions, presentation and evaluator intact. Archive program-v2 byte-for-byte as guidedCisProgramV2.json; reviewed current program becomes cis-v8.1-program-3. Corrected Control1 content gets an additive guidedControl1V4.json pack only where necessary; original versions remain readable. Legacy interviews use the approved UI without an old-style fallback. Current-version rebasing requires explicit user comparison plus existing tenant/CAS/base guards, retains same-version answers/manual text and archives history. Version upgrades are explicit and map only semantically unchanged stable fields/rows; genuinely new or changed clauses remain unanswered. No silent bulk migration or assessment regeneration.

Reuse the approved grouped interview and one complete plain-text summary. Current Implementation contains OVERVIEW, IMPLEMENTATION BREAKDOWN and ITEMS TO ADDRESS, with actual client/id/title and separate proposed status. Native payload is exactly the reviewed text including line breaks/user edits; submission never regenerates it. Native Save/Update/summary Save & close share the existing authoritative write and replacement confirmation; close only after success. Questions save interview progress only. Failure/cancel/manual edits/stale/conflict/duplicate guards remain.

Only appropriate context/counts/questions/generated content vary. Artwork, fonts/colors/spacing/layout/styles, greetings/launcher/window behavior, native page design/accessibility and excluded frameworks stay frozen. No new dependencies/integrations/scoring system or unrelated cleanup.
